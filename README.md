# proxyrec

Записывает HTTP-трафик стороннего приложения в тесты, затем повторяет запросы и сравнивает ответы с записанными.

## Установка

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

Все команды запускаются из папки проекта: `.venv\Scripts\python -m proxyrec <команда>`.

## Веб-интерфейс

```
python -m proxyrec ui            # http://127.0.0.1:8000, браузер откроется сам
python -m proxyrec ui --port 9000 --no-browser
```

Всё, что умеет CLI, доступно в интерфейсе:
- **Запись.** Запуск и остановка из браузера, запросы появляются по мере записи. После остановки сразу показываются кандидаты для корреляции.
- **Прогон.** Одного теста или всех. Поле «Целевой адрес» в шапке работает как `--target`.
- **Разбор шага.** Эталон и фактический ответ рядом, отличия по полям, построчный diff для текста.
- **Игнор.** Кнопка «игнорировать» у отличия добавляет правило. Прогон сразу пересчитывается по уже полученным ответам, без повторной отправки запросов.
- **Приём ответа.** «Принять фактический ответ» для шага или «Принять все упавшие».
- **Правила.** Списки игнора и корреляции, ручное добавление и удаление. Можно удалять шаги и тесты.

## Как работать из командной строки

1. **Запись**
   ```
   python -m proxyrec record login_flow
   ```
   Поднимается прокси `127.0.0.1:8888`. Укажите его в настройках приложения (или `HTTP_PROXY=http://127.0.0.1:8888`), выполните действия и нажмите Enter.

   Если приложение не умеет работать через прокси, используйте reverse-режим и направьте приложение на `http://127.0.0.1:8888`:
   ```
   python -m proxyrec record login_flow --reverse http://backend:8080
   ```
   Другие опции: `--host api.local` (записывать только этот хост), `--keep-static` (не отбрасывать js/css/картинки), `--port`, `--overwrite`.

2. **Корреляция** — значения, которые сервер выдал, а клиент отправил дальше (токены, id созданных объектов):
   ```
   python -m proxyrec correlate login_flow           # показать кандидатов
   python -m proxyrec correlate login_flow --apply   # сохранить правила
   ```
   При прогоне такие значения берутся из нового ответа и подставляются в следующие запросы. В ответах их изменение не считается ошибкой. Куки из `Set-Cookie` обрабатываются автоматически.

3. **Прогон**
   ```
   python -m proxyrec run                  # все тесты
   python -m proxyrec run login_flow -v    # один тест, все отличия
   python -m proxyrec run --target http://staging:8080
   ```
   Если хоть один тест упал, код выхода — 1 (удобно для CI).

4. **Тест упал**: посмотрите отличия (`diff <имя>`) и проверьте приложение вручную.
   - Новое поведение верное, обновить эталон: `python -m proxyrec accept login_flow` (все упавшие шаги) или `--step 3`.
   - Поле меняется всегда (время, случайный id): добавьте игнор:
     ```
     python -m proxyrec ignore login_flow "**.timestamp"
     python -m proxyrec ignore login_flow "data.items[*].updatedAt" --step 4
     python -m proxyrec ignore login_flow "\d{4}-\d{2}-\d{2}T[\d:.]+" --regex
     python -m proxyrec ignore login_flow etag --header
     ```

Другие команды: `list` — тесты и результат последнего прогона, `show <имя>` — шаги теста.

## Время ответа

При записи сохраняется время каждого ответа, при прогоне каждый запрос замеряется (включая загрузку тела). Если задан лимит и ответ пришёл медленнее, шаг падает с причиной «превышено время». Это отдельно от «ответ отличается», возможны обе причины сразу.

Лимит задаётся в миллисекундах. Действует самый конкретный:
1. лимит шага: `python -m proxyrec limit <тест> 500 --step 3`;
2. лимит теста: `python -m proxyrec limit <тест> 2000`, снять — `limit <тест> off`;
3. лимит прогона: `python -m proxyrec run --max-time 1000`, в интерфейсе — поле «Лимит, мс» в шапке;
4. общий лимит: `"max_time_ms"` в `proxyrec.json`.

Изменение лимита сразу пересчитывает последний прогон по уже замеренному времени. `accept` по умолчанию обновляет эталон только у шагов, где отличается ответ: превышение времени остаётся ошибкой, пока не изменится лимит или скорость сервера.

Вывод упавшего теста:
```
FAIL  заказ (упало 2 из 7 — по времени: 1, по ответу: 1; 1830 мс)
    шаг 3: GET http://api/orders/42  (1204 мс)
      время отклика: 1204 мс > лимита 500 мс
    шаг 5: GET http://api/page  (35 мс)
      ответ отличается:
        $.status: "NEW" -> "PAID"
```

## Что сравнивается

- статус ответа;
- заголовки из `compare_headers` (по умолчанию только `Content-Type`);
- тело: JSON сравнивается по полям с указанием пути (`$.data.items[0].id: "a" -> "b"`), текст — построчным diff.

Синтаксис JSON-путей: `a.b[0].c`, `*` — любой ключ или индекс, `[*]` — любой индекс, `**` — любая глубина.

## Файлы

```
recordings/<имя>/test.json      — тест: шаги (запрос + эталонный ответ), ignore, extract
recordings/<имя>/last_run.json  — результат последнего прогона (из него берёт accept)
proxyrec.json              — необязательный общий конфиг
```

Пример `proxyrec.json`:
```json
{
  "tests_dir": "recordings",
  "compare_headers": ["content-type"],
  "max_time_ms": null,
  "ignore": {"json_paths": ["**.timestamp", "**.requestId"], "regex": [], "headers": []}
}
```

`test.json` — обычный JSON, его можно править вручную: удалять лишние шаги, менять правила `extract` и `ignore`. У шага может быть свой блок `ignore`.

Правила `extract` бывают трёх видов:
```json
{"var": "token", "step": 1, "from": "json",   "path": "$.access_token", "value": "<записанное значение>"}
{"var": "loc",   "step": 2, "from": "header", "name": "Location", "regex": "/orders/(\\w+)", "value": "..."}
{"var": "csrf",  "step": 1, "from": "regex",  "regex": "name=\"csrf\" value=\"(\\w+)\"", "value": "..."}
```

## Автотесты

```
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest
```
- `tests/test_units.py` — сравнение, JSON-пути, корреляция.
- `tests/test_e2e.py` — CLI: запись через настоящий прокси и прогон против демо-сервера из `tests/conftest.py`.
- `tests/test_server.py` — API интерфейса.
- `tests/test_ui.py` — интерфейс в headless Chrome через playwright. Пропускается, если нет Chrome. Скриншоты: `PROXYREC_SHOTS=<папка>`.
